# V998 — SHARK functional client flow

Candidate under validation; not a production or v1 completion certificate.

- One typed request contract for panel/API and full-page forms, including legacy selection aliases. Invalid bodies/aliases and contradictions between permitted selections are rejected before question allowance and context persistence. An unavailable explicit advice selection remains redacted and is never silently replaced by another advice item; its valid question follows the existing allowance policy.
- Selected permitted advice derives its own match. Existing publication/plan authorization remains before normalization. An unrelated match cannot be silently attached to that advice.
- Server-rendered context survives match-page panel submission and no-JavaScript full-page forms. Existing CSRF, pending latch, session-transition clearing and text-only responses remain.
- Accepted submissions write at most one snapshot. Large snapshots remain valid JSON with explicit reduction metadata.
- Local answers distinguish live/agenda/favorites/plan intents, reuse prepared fixture identity and account-owned favorites, and expose missing versus empty observations. Limits describe configuration, not guaranteed publication.
- Recorded advice fields remain distinct from presentation defaults; a missing confidence/stake/risk is not fabricated. The confidence field is an internal index, not a win probability.
- Answers use the actual session/browser locale (ES/EN/FR). Client generation metadata describes actual local execution independently from credential presence.
